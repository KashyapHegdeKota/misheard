# Misheard: a map of where speech models get it wrong

A single landing page. It shows which kinds of real conversational audio today's speech
models get wrong, with the evidence one click away: every dot on the map is a clip you can
hear and read.

Next.js (App Router, TypeScript), deck.gl for the map, wavesurfer.js for waveforms, Framer
Motion for the quiet animation. It builds to a fully static site (`output: "export"`): no
server code, no environment variables, deployable to Vercel as is.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # writes the static site to out/
npm run preview    # serves out/ at http://localhost:3000 (supports audio seeking)
```

## Where the numbers come from

Nothing about results is written in a component. Every number, label and transcript on the
page is read from **`public/data/clips.json`**, the file the data pipeline produces
(contract below), plus **`public/audio/<id>.mp3`** for the sound.

`npm run dev` and `npm run build` first run `scripts/prepare-data.mjs`, which reads
`clips.json` alone, checks it against the contract, and derives what the site needs:

| derived file                  | what it is                                                        | who reads it                          |
| ----------------------------- | ----------------------------------------------------------------- | ------------------------------------- |
| `generated/site.json`         | `meta` + `summary` + the few clips the page renders statically    | the server-rendered page (build time) |
| `public/data/points.json`     | position, tags and per-model WER of every clip (about 250 KB)     | hero and map, fetched after first paint |
| `public/data/clip/<id>.json`  | one full clip: words, alignments, every model's result            | map panel and worst-10 player, on click |

Audio is never preloaded: a clip's file is fetched when someone presses play or opens it.

### Dropping in the real data

1. Put the pipeline's `clips.json` at `web/public/data/clips.json` and its audio at
   `web/public/audio/<id>.mp3` (the `audio` field of each clip is relative to the site root).
2. `npm run build`. That is all. Models, finding keys, conditions and tag values are read
   from the file; nothing is assumed.

If `clips.json` is **absent** the build uses a clearly fake fixture instead
(`public/data/clips.sample.json`, tone audio in `public/audio-sample/`, generated by
`npm run sample`) and the page shows a "Sample data" banner and a `[Sample data]` title. If
`clips.json` is present the fixture is deleted from `public/` so it cannot ship alongside real
data, and an invalid `clips.json` fails the build with a list of what is wrong; it never
falls back to the fixture.

The build prints warnings for things that degrade gracefully (clips with no result for a
model, no `words[]`, alignments that disagree with `words[]`, audio files that are not in
`public/` yet) and stops on things that would put a wrong figure on the page.

## The data contract

```jsonc
{
  "meta": { "dataset", "models": [{ "id", "label", "detail" }], "primary_model", "metric", "n_clips", "generated_at" },
  "clips": [{
    "id", "x", "y", "audio", "duration", "meeting", "mic",
    "tags": { "snr_db", "noise", "overlap_ratio", "overlap", "wpm", "speed", "n_speakers", "accent", "native_languages" },
    "conditions": ["clean|noisy|overlapping|accented"],
    "ref", "words": [{ "w", "start", "end", "speaker" }],
    "results": { "<model id>": { "hyp", "wer", "ops": [{ "op": "equal|sub|del|ins", "ref", "hyp" }] } }
  }],
  "summary": { "by_condition", "headline", "findings": [ /* 3 */ ], "worst10", "karaoke_clip" }
}
```

What the site does with it:

- **Hero**: `summary.headline` becomes "Whisper's error rate jumps from X% to Y% when two people
  talk at once." The family name is the model label cut before the first size or version token;
  the condition wording is chosen from `to_condition` (`lib/wording.ts`). Dots are colored by the
  primary model's WER.
- **Hear it vs. read it**: `summary.karaoke_clip`, timed from `words[]` (the *i*-th
  reference-bearing op is `words[i]`). A substitution is the model's word in red, crossed out,
  with the right word in green above it; a deletion is a dashed gap with the missed word above;
  an insertion is a red crossed-out word tagged "extra" (it has no reference word, so it appears
  when the previous reference word ends).
- **Findings**: one card per `summary.findings` entry: its `stat`, a bar chart of its `chart`
  (bars are the primary model; every other model is a white tick), and a play button for its
  `example_clip`.
- **Map**: every clip from `points.json`. Filters are built from the tag values present in the
  data. The "WER" readout over the matching clips is pooled (total errors over total reference
  words), computed in the browser from per-clip error counts.
- **Face-off**: `summary.by_condition`; columns are the conditions present, plus "All clips".
- **What data would fix this**: one item per finding, copy from `content/recommendations.ts`
  looked up by `finding.key`, evidence line from the data (see below).
- **Footer**: `meta.dataset` (which carries the license), `meta.models` (label and detail),
  `meta.metric`, clip count and `generated_at`.

## The one color scale

Green → amber → red for word error rate, defined once in `lib/color.ts` (OKLCH, saturating at
50% WER). It colors the hero and map dots, table cells, chart bars, the WER numbers and the
transcript marks. Nothing else on the page carries a hue. Color is never the only signal: every
cell and bar prints its value, and transcript errors also use strike-through, a dashed gap, or a
"+" mark.

## Copy that needs the real results: `content/recommendations.ts`

The "What data would fix this" copy is **draft**, written before the results existed. It is keyed
to the finding keys (`overlap`, `noise`, `accent`) and contains no numbers; the figures beside each
item come from `summary.findings[].stat`. While `COPY_STATUS` is `"draft"` the page shows a small
"Draft copy" tag. Rewrite the copy against the real numbers, check the keys against
`summary.findings[].key` (the build logs any key with no copy; such an item still renders, with its
title and evidence from the data), then set `COPY_STATUS` to `"final"`.

## Layout of the code

```
app/                 layout, page (composes the sections), global styles, favicon
components/          one file per section/part, each with its CSS module
  Hero, HeroField    headline + the canvas dot field (plain 2D canvas: paints before any heavy chunk loads)
  HearSection, Karaoke
  Findings, MiniChart, PlayExample
  MapSection, MapExplorer, MapFilters, MapCanvas (deck.gl, loaded only near the map), ClipPanel
  ClipDetail, Waveform (wavesurfer.js), Transcript (side-by-side diff), WorstPlayer (<dialog>)
  FaceOff, Recommendations, Footer, SampleBanner
content/             recommendations.ts
lib/                 types, color scale, formatting/wording, alignment → tokens (diff.ts),
                     audio player + one-at-a-time playback, data fetching, map store
scripts/             prepare-data.mjs (build step), make-sample-data.mjs (fixture), serve-static.mjs
e2e/                 browser checks (see below)
```

## Checking the site

`e2e/run.mjs` drives the built site in headless Chromium and checks it against the data it was
built from (`generated/site.json`, `public/data/points.json`): hero, karaoke sync, each
finding's audio, map filters, a dot click with waveform and transcripts, the worst-10 player,
the table, keyboard use, phone width and reduced motion. It is not a dependency of the site:

```bash
npm i --no-save playwright && npx playwright install chromium
npm run build && npm run preview &     # then, in another shell:
npm run e2e                            # or: npm run e2e -- karaoke map
```

Run it after dropping in the real data: its expectations come from the data, not from the fixture.

## Notes

- The map needs WebGL 2. Without it the map explains that and the rest of the page still works.
- Audio: one clip plays at a time across the whole page. A missing audio file shows
  "not available" instead of failing.
- Motion respects `prefers-reduced-motion`: the hero dots stop drifting, sections stop animating in,
  map transitions are instant.
- On touch screens a vertical swipe over the map scrolls the page; pinch zooms the map. On a
  desktop, scroll past the map as usual and use Ctrl/⌘ + scroll, the + and − buttons, or `+`/`-`
  to zoom.
